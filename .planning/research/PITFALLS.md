# Pitfalls Research: LLM Analysis Service

**Domain:** LLM-powered transcription analysis
**Date:** 2026-03-22
**Context:** Adding OpenAI GPT analysis to existing audio transcription platform

## Critical Pitfalls

### 1. Naive Full-Transcript Sends (без chunking)
- **Проблема:** Отправка полной транскрипции 90+ мин записи в один запрос. GPT-4o context = 128K, но "lost in the middle" — модель плохо обрабатывает информацию в середине длинного контекста
- **Признаки:** Summary пропускает важные моменты из середины записи, action items только из начала/конца
- **Предотвращение:** Map-reduce для транскрипций > 8K токенов. Chunking по сегментам спикеров (не по символам). tiktoken для точного подсчёта
- **Фаза:** Foundation — заложить chunking сразу

### 2. Отсутствие кэширования результатов
- **Проблема:** Повторный запрос того же summary вызывает OpenAI заново. 3-10x перерасход токенов
- **Признаки:** Высокие счета OpenAI, медленные повторные запросы
- **Предотвращение:** Кэш в MongoDB по ключу (recording_id, type, prompt_version). Инвалидация при смене промпта
- **Фаза:** Core — реализовать вместе с первыми анализами

### 3. Галлюцинации LLM в summary и action items
- **Проблема:** Модель "додумывает" решения, обязательства, факты, которых нет в транскрипции
- **Признаки:** Action items с конкретными дедлайнами, которые не упоминались; выводы, не следующие из текста
- **Предотвращение:**
  - System prompt: "Only extract information explicitly stated in the transcript"
  - Для action items: требовать цитату из транскрипции
  - Temperature = 0.1-0.3 для аналитических задач
- **Фаза:** Prompt engineering — итерировать с первых промптов

### 4. Неконтролируемые расходы на API
- **Проблема:** Нет лимитов — один пользователь может сгенерировать тысячи запросов
- **Признаки:** Неожиданный рост счёта OpenAI
- **Предотвращение:**
  - Rate limiting по user_id (X запросов/час)
  - Использовать gpt-4o-mini по умолчанию (10-20x дешевле gpt-4o)
  - Логирование usage (prompt_tokens, completion_tokens) на каждый запрос
- **Фаза:** Foundation — заложить логирование и лимиты сразу

## Moderate Pitfalls

### 5. Chat context grows unbounded
- **Проблема:** Каждое сообщение отправляет полную транскрипцию + полную историю. Стоимость растёт линейно с каждым сообщением
- **Признаки:** 10-е сообщение в чате стоит 10x дороже первого
- **Предотвращение:**
  - Ограничение истории (последние N сообщений)
  - Сжатие старых сообщений в summary
  - Транскрипция в system prompt обрезается до релевантных секций
- **Фаза:** Chat implementation

### 6. Синхронные вызовы OpenAI блокируют FastAPI
- **Проблема:** OpenAI отвечает 5-20 секунд. Синхронный вызов блокирует worker
- **Признаки:** Таймауты, медленный API под нагрузкой
- **Предотвращение:** AsyncOpenAI client — нативно async, не блокирует event loop
- **Фаза:** Foundation — использовать async client с самого начала

### 7. Хардкод промптов в коде
- **Проблема:** Промпты в Python-строках. Каждая итерация = изменение кода + деплой
- **Признаки:** Частые деплои ради изменения формулировки промпта
- **Предотвращение:** Промпты как Jinja2 файлы в `src/prompts/`. Версионирование. Параметризация
- **Фаза:** Foundation — PromptManager с самого начала

### 8. Неструктурированный ответ LLM
- **Проблема:** `json.loads()` на свободный текст LLM. Ломается на edge cases
- **Признаки:** Парсинг ошибки, inconsistent формат ответов
- **Предотвращение:**
  - `response_format={"type": "json_object"}` в OpenAI API
  - Pydantic модели для валидации ответа
  - Retry при невалидном ответе
- **Фаза:** LLMClient — заложить structured output сразу

### 9. Данные диаризации не используются в промптах
- **Проблема:** Отправлять в LLM только текст без спикеров — теряется ключевая информация
- **Признаки:** Action items без ответственного, summary без атрибуции
- **Предотвращение:** TranscriptionReader форматирует текст с метками спикеров: `[Speaker 1, 00:05:30]: текст...`
- **Фаза:** TranscriptionReader — формат вывода с диаризацией

## Minor Pitfalls

### 10. Ошибки WhisperX усиливаются LLM
- **Проблема:** Ошибки транскрипции (неправильные слова, пропущенные фразы) LLM воспринимает как факт
- **Предотвращение:** В system prompt: "The transcript may contain speech recognition errors. Use context to interpret unclear passages"

### 11. Нет graceful degradation при недоступности OpenAI
- **Проблема:** OpenAI API down → весь сервис анализа недоступен
- **Предотвращение:** Возвращать кэшированные результаты, информативная ошибка для новых запросов, health check эндпоинт

### 12. Несоответствие языка промпта и транскрипции
- **Проблема:** Английский промпт + русская транскрипция → непредсказуемый язык ответа
- **Предотвращение:** Определять язык транскрипции, адаптировать промпт. Или явно указывать: "Respond in the same language as the transcript"
