# Features Research: LLM Transcription Analysis

**Domain:** Audio transcription analysis platforms
**Date:** 2026-03-22
**Competitors analyzed:** Otter.ai, Fireflies.ai, Fathom, tl;dv, Granola, Recall.ai

## Table Stakes (must have)

Без этих функций продукт не конкурентоспособен.

### 1. Summary (краткое содержание)
- **Что:** Сжатый пересказ записи в 3-5 абзацев
- **Ожидаемое поведение:** Учитывает спикеров, сохраняет ключевые решения, хронологический порядок
- **Сложность:** Low-Medium
- **Зависимости:** Транскрипция + диаризация

### 2. Key Points (ключевые тезисы)
- **Что:** Список из 5-10 главных мыслей/выводов
- **Ожидаемое поведение:** Bullet points, каждый — самодостаточное утверждение
- **Сложность:** Low
- **Зависимости:** Транскрипция

### 3. Action Items
- **Что:** Извлечение обязательств ("кто что обещал сделать")
- **Ожидаемое поведение:** Формат: [Ответственный] — [Действие] — [Срок если упомянут]
- **Сложность:** Medium (требует хорошей диаризации для атрибуции)
- **Зависимости:** Транскрипция + диаризация (для определения "кто")

### 4. Кэширование результатов
- **Что:** Повторный запрос того же анализа возвращает сохранённый результат
- **Ожидаемое поведение:** Мгновенный ответ для уже сгенерированного анализа
- **Сложность:** Low
- **Зависимости:** MongoDB

### 5. Обработка длинных транскрипций
- **Что:** Корректная работа с записями 60-120+ минут
- **Ожидаемое поведение:** Прозрачно для пользователя, качество не деградирует
- **Сложность:** High — требует chunking стратегии (map-reduce или hierarchical)
- **Зависимости:** tiktoken для подсчёта токенов
- **Оценки:** 15 мин ≈ 4K токенов, 60 мин ≈ 15K, 120 мин ≈ 30K+

## Differentiators (конкурентное преимущество)

### 6. FAQ генерация
- **Что:** Автоматическое создание вопросов-ответов по материалу
- **Ожидаемое поведение:** 5-10 релевантных Q&A, покрывающих основные темы
- **Сложность:** Medium
- **Зависимости:** Транскрипция
- **Почему дифференциатор:** Мало кто из конкурентов делает это; особенно ценно для лекций

### 7. Chat with Transcript (свободный чат)
- **Что:** Пользователь задаёт вопросы по записи, LLM отвечает с контекстом
- **Ожидаемое поведение:** Ответ с цитатами из транскрипции, сохранение истории чата
- **Сложность:** High — управление контекстом, история сессий, длинные транскрипции
- **Зависимости:** Все предыдущие компоненты

### 8. Speaker Attribution в анализе
- **Что:** Все результаты (summary, action items) привязаны к конкретным спикерам
- **Ожидаемое поведение:** "Speaker 1 предложил...", "Speaker 2 взял обязательство..."
- **Сложность:** Low (данные из диаризации уже есть)
- **Зависимости:** Диаризация

### 9. Регенерация результата
- **Что:** Кнопка "сгенерировать заново" для любого анализа
- **Ожидаемое поведение:** Новый вызов LLM, замена предыдущего результата
- **Сложность:** Low
- **Зависимости:** Кэширование

## Anti-Features (не делать)

| Feature | Причина |
|---------|---------|
| Auto-analysis (автоматический запуск после транскрипции) | Сжигает токены на записи, которые пользователь может не открыть |
| SSE/WebSocket streaming ответов | Усложняет архитектуру; для v1 достаточно HTTP poll/wait |
| Fine-tuning моделей | Не нужен для 4 типовых задач, GPT-4o-mini справляется из коробки |
| Live analysis (анализ в реальном времени) | Нет live-транскрипции в пайплайне |
| Cross-recording comparison | Требует RAG инфраструктуру, не MVP |
| Export в PDF/DOCX | Фронтенд задача, не бэкенд |
| Редактирование транскрипции | Другой сервис, не LLM-анализ |

## Feature Dependency Graph

```
Транскрипция + Диаризация (existing)
    │
    ├── Summary ──────────┐
    ├── Key Points ────────┤
    ├── Action Items ──────┤── Кэширование → Регенерация
    ├── FAQ ───────────────┘
    │
    └── Chat with Transcript (зависит от всех выше + история сессий)
```

## MVP приоритизация

**Wave 1 (foundation):** Базовый сервис + Summary + Key Points
**Wave 2 (core):** Action Items + FAQ + кэширование
**Wave 3 (advanced):** Chat with Transcript + регенерация
